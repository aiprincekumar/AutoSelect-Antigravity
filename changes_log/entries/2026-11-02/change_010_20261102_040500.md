## 📝 Problem Statement

User reported that the window targeting and auto-focus for Antigravity in Keyboard Automation was only searching and not actually restoring, maximizing, or bringing the Antigravity window to the screen:
"एंटी-ग्रेविटी को जो फोकस में लाने का बात था, वो एक काम नहीं कर रहा है। सिर्फ सर्च कर रहा है, डिटेक्ट कर रहा है लेकिन एंटी-ग्रेविटी को ऑन द स्क्रीन और फोकस अप बढ़ा करने का ये सब जो काम है कुछ भी नहीं कर रहा है। इसके लिए इधर देखो। मैं जो यूज़ कर रहा हूँ एंटी-ग्रेविटी आईटी नहीं है, एंटी-ग्रेविटी 2.0 हार्नेस है।"

## 🔍 Root Cause Analysis

1. **Title Discrepancy in Antigravity 2.0 Harness:**
   - In Antigravity 2.0 Harness, the active window title contains conversation or project names (e.g. `'Hybrid Mouse Keyboard Con...'` or `'Identifying Chats With Gr...'`), NOT the word "Antigravity".
   - The legacy window selector strictly filtered by title substring containing "Antigravity", causing zero matches.
2. **Process-Level Detection Missing:**
   - The window is hosted by `Antigravity.exe` (PID 15024) under class `Chrome_WidgetWin_1`. Legacy detection did not inspect process images or class names.
3. **Desktop Session Context:**
   - When running from subshells or background tasks, thread desktops were detached from the active input desktop.
4. **ctypes Struct Clashes Across Modules:**
   - Redefined `RECT`, `WNDENUMPROC`, and `WINDOWPLACEMENT` caused ctypes `ArgumentError` when discovering tests.
5. **Windows 10/11 Foreground Lock Restrictions:**
   - Simple `ShowWindow` and `SetForegroundWindow` calls were blocked by OS focus stealing prevention.

## 🛠️ Solutions Implemented

1. **Multi-Strategy Detection Engine:**
   - Process signature matching (`Antigravity.exe`, `electron.exe`).
   - Window class identification (`Chrome_WidgetWin_1`).
   - Multi-keyword comma-separated matching with default: `"Antigravity,Antigravity 2.0,Harness,AutoSelect-Commander"`.
   - Thread desktop attachment via `OpenInputDesktop(0, False, 0x01FF)` and `SetThreadDesktop`.
2. **Battle-Tested Window Restoration, Maximization & Force-Focus Pipeline:**
   - Un-minimize minimized windows via `ShowWindow(hwnd, SW_RESTORE)`, `ShowWindowAsync`, and `OpenIcon`.
   - Full-screen maximize via `ShowWindow(hwnd, SW_MAXIMIZE)` and `ShowWindowAsync`.
   - Windows 10/11 foreground lock bypass via `AllowSetForegroundWindow(ASFW_ANY)`, virtual `VK_MENU` (Alt) down/up pulse, dual-thread `AttachThreadInput`, Z-order topmost bumping (`HWND_TOPMOST` ➔ `HWND_NOTOPMOST`), `BringWindowToTop`, `SetForegroundWindow`, `SwitchToThisWindow`, and `SetFocus`.
   - Post-verification loop certifying geometry bounds, maximized status, and foreground focus.
3. **ctypes Interoperability Fix:**
   - Standardized on `wintypes.RECT` and `ctypes.c_void_p` in `argtypes` for callbacks and placements across `Keyboard Automation/grill_me_automation.py` and `auto_commander/platform/win32_window.py`.
4. **Comprehensive Test Suite & Documentation:**
   - Updated `tests/test_grill_me.py` to cover multi-keyword matching, candidate enumeration, and geometry verification (85/85 tests passing).
   - Updated `run_grill_me.bat`, `run_grill_me.ps1`, and `README.md`.
