## 🔍 Detailed Log: CHG-011

- **Component:** `Keyboard Automation/`
- **Scope:** Strictly exclude web browsers (Chrome, Edge, Firefox, Brave, etc.) and enforce exact Antigravity process targeting.
- **Key Enhancements:**
  - Diagnosed root cause: Google Chrome (`chrome.exe`) and Antigravity 2.0 share the exact same window class (`Chrome_WidgetWin_1`). Without browser disqualification, Chrome received positive scores and was focused, causing `Ctrl + L` to focus the browser omnibox and type `1` + `Enter` (performing an accidental web search).
  - Added strict browser disqualification (`DISQUALIFIED_BROWSER_PROCS`) across `grill_me_automation.py`, `activating_grill_me.py`, and `win32_window.py`.
  - Enforced Antigravity 2.0 priority targeting: matching `Antigravity.exe` or image path yields highest priority (+1000 score).
  - Restricted `Chrome_WidgetWin_1` class scoring strictly to verified Antigravity/Electron processes.
  - Added robust Win32 fallback via `QueryFullProcessImageNameW` in `get_process_info_for_hwnd`.
  - Added structured selection logging (`Selected Window: HWND=..., Process=... (PID=...), Title=..., Class=...`) and pre-execution foreground browser check.
  - Added unit tests in `tests/test_grill_me.py` (93/93 tests passing, 0 gitleaks leaks).
