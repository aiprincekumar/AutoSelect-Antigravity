## 📝 Problem Statement

User reported that Grill Me automation was focusing Google Chrome instead of Antigravity, and typing into Chrome's address bar to perform searches:
"यह एंटी ग्रैविटी को न फोकस करके क्रोम ब्राउजर को फोकस कर रहा है और उसी में कुछ-कुछ सर्च करने लग रहा है, इसको फिक्स करो। ये एंटी ग्रैविटी 2.0 में ही होना चाहिए।"

## 🔍 Root Cause Analysis

1. **Chromium Window Class Overlap:**
   - Google Chrome (`chrome.exe`) and Electron applications (including Antigravity 2.0) share the exact same top-level window class name: `Chrome_WidgetWin_1`.
2. **Missing Browser Blacklist:**
   - Neither `grill_me_automation.py` nor `win32_window.py` had web browsers in their exclusion blacklist.
   - Any Chrome window with class `Chrome_WidgetWin_1` received positive weighting (+15 for class, +15 for visible, +10 for maximized = +40 score).
3. **Keyword Matching on Browser Tabs:**
   - If Chrome had a tab open mentioning workspace keywords (e.g. GitHub "AutoSelect-Commander", Antigravity docs, YouTube), Chrome accumulated 90+ points.
4. **Accidental Address Bar Focus & Search:**
   - When Chrome was focused, step 1 pressed `Ctrl + L` (which selects the Chrome URL address bar/omnibox). Step 3 pressed `1`, and Step 4 pressed `Enter`, triggering a Google search for "1" inside Google Chrome!

## 🛠️ Solutions Implemented

1. **Explicit Web Browser Disqualification:**
   - Added `DISQUALIFIED_BROWSER_PROCS = {"chrome.exe", "msedge.exe", "firefox.exe", "brave.exe", "opera.exe", "vivaldi.exe", "iexplore.exe", "safari.exe"}` across:
     - `Keyboard Automation/grill_me_automation.py`
     - `Activating Grill Me Chat in anti-gravity/activating_grill_me.py`
     - `auto_commander/platform/win32_window.py`
   - Candidates running as any browser are strictly disqualified (`continue` / score `-9999`) unless the user explicitly requests a browser via CLI (e.g. `--target chrome`).
2. **Highest Priority Antigravity 2.0 Process Targeting:**
   - Matched specifically by process executable `antigravity.exe` or process image path containing `antigravity`.
   - Assigned highest priority score (+1000) for `Antigravity.exe`.
   - Window class `Chrome_WidgetWin_1` bonus is now strictly restricted to verified Antigravity/Electron processes, completely preventing arbitrary Chromium windows from gaining score.
3. **Robust Win32 Process Image Resolution Fallback:**
   - Enhanced `get_process_info_for_hwnd` with native `kernel32.OpenProcess(0x1000)` and `QueryFullProcessImageNameW` so process names and paths are never missed even when `psutil` permissions fail.
4. **Defense-in-Depth Foreground & Pre-Execution Gatekeepers:**
   - Added clear structured logging in the mandatory format:
     `Selected Window: HWND=<hwnd>, Process=<proc_name> (PID=<pid>), Title='<title>', Class=<class>`
   - In `prepare_target_window`: verifies `process_name != 'chrome.exe'`; immediately aborts if a browser is detected.
   - In `execute()`: inspects the live foreground window immediately before key simulation; if `chrome.exe` or any browser has foreground focus, aborts execution immediately with a warning to protect user tabs.
5. **Comprehensive Unit Tests:**
   - Added tests in `tests/test_grill_me.py` verifying browser disqualification, Antigravity priority, rejection when only browsers are open, and pre-execution foreground abort (93/93 tests passing).
