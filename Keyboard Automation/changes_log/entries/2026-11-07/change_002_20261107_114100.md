## 1. Problem Statement & Root Cause
In multi-question questionnaires, when a questionnaire had fewer options than total questions ($N$), `_execute_cdp_hybrid` in `core_engine/automator.py` fell back to `opts[-1]`, repeating the last option (e.g. dispatching '3' and then '3' again). Furthermore, Step 2 unverified DOM counts could overwrite ground truth question counts from `target_chat.json`, inflating question counts and causing spurious keystrokes (such as option 2 followed by 3 and 3).

## 2. Solution & Architectural Enhancements
1. **Strict Padding to Default Option 1:** In `core_engine/automator.py` (`_execute_cdp_hybrid` and constructor), options list is strictly padded with `"1"` when `len(opts) < tq`, completely eliminating `opts[-1]` repeats.
2. **Ground Truth Preservation in Step 2:** In `step_2_chat_and_focus/step2_gui_chat_select.py`, existing questions count and questions list from state data are preserved and never overwritten by unverified DOM estimates.
3. **Step 1 Strict Option 1 Defaulting:** In `step_1_chat_identifier/step1_find_and_focus.py`, `QuestionPayload` case-insensitively checks for `(Recommended)` / `[Recommended]`, strictly defaulting to option index 1 when no recommended tag is found.
4. **Step 9 Complete Automation Forwarding:** In `step_9_complete_automation/complete_automation.py`, padded option sequences are forwarded strictly matching ground truth question counts.
